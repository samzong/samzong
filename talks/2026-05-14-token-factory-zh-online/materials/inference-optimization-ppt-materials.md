来源：`talks/2026-05-14-token-factory-zh-online/推理优化PPTv0.1.0.pptx`

用途：封存 DaoCloud 技术先进性、推理优化能力、InferX 产品化能力、硬件适配案例、推理加速收益数据，作为 Token Factory PPT 与官网中“为什么 DaoCloud 能做成 Token Factory”的核心素材。

- 本材料中的数字按用户当前确认，先作为真实素材使用。

## 一句话定位

这份 PPT 的主线是：推理优化不是把模型“调快一点”，而是把 GPU 从闲置资产变成高周转生产资料，让每张卡在生产环境里持续产出 Token、收入和可承诺的服务质量。

## 对 Token Factory 的意义

Token Factory 要说服 C 类客户购买，不能只讲 MaaS 界面、计费、租户、Dashboard 和 Copilot，还必须证明 DaoCloud 能把底层推理服务真正跑快、跑稳、跑便宜。

这份 PPT 提供了三类关键证据：

- 技术先进性：Kubernetes 分布式系统能力 + vLLM / llm-d / SGLang 推理引擎深度优化。
- 生产级能力：部署、调度、加速、路由、韧性、观测、Planner、经验库闭环。
- 案例证明：NVIDIA 新架构、异构集群、国产 DCU、A800 通用基线等不同硬件和模型形态下均有可量化收益。

### Slide 3：每张卡挣钱

标题：

> 优化不是“调快一点”，而是让每张卡挣钱

核心表达：

四个指标：

| 指标 | 经营含义 |
|---|---|
| 吞吐 | 决定单位时间收入上限 |
| 利用率 | 决定固定资产周转效率 |
| TTFT / TPOT | 决定用户体验和可售并发 |
| SLA | 决定能不能进入生产环境 |

示例收益：

| 状态 | 吞吐 | 利用率 | 收入 | 成本 |
|---|---:|---:|---:|---:|
| 优化前 | 2000 tok/s | 50% | 0.52 万/卡/月 | 0.68 万/卡/月 |
| 优化后 | 2400 tok/s | 75% | 0.93 万/卡/月 | 0.68 万/卡/月 |

图表数据：

- 收入 / 万元·卡·月：优化前 0.52，优化后 0.93。
- 成本 / 万元·卡·月：优化前 0.68，优化后 0.68。

可用于销售主张：

- 同一张卡、同样成本，通过吞吐和利用率优化，从亏损或低收益走向更高收益。
- Token Factory 的底层价值不是“监控 GPU”，而是提高 GPU 单卡月产出。

### Slide 15：Prefill / Decode 分段优化

标题：

> 推理加速要按 Prefill / Decode 两段拆开看

核心表达：

- 两段瓶颈不同，优化抓手也不同。
- 统一调参很难得到稳定收益。

| 阶段 | 主要瓶颈 | 优化抓手 |
|---|---|---|
| Prefill | Attention / FFN 计算深度、长上下文 KV 写入 | TP/EP、Chunked Prefill、高效 Attention Kernel、KV 复用 |
| Decode | 单步生成、显存墙、通信与 all-to-all | EP、EPLB、Spec Decode / MTP、异步调度、Batch 策略 |
| 跨阶段 | 缓存命中、Offload、通信后端选择 | KV Cache Offload、NIXL/NCCL/UCX/DeepEP、FP8/FP4 |

可用于技术先进性：

- DaoCloud 能做模型阶段级别的瓶颈分析，不是单一参数优化。

### Slide 16：KV Cache

能力：

| 能力 | 内容 |
|---|---|
| 复用 | 多轮对话 / Agent ReAct / 前缀命中 |
| 分层 | GPU HBM / CPU Memory / 高速网络存储 |
| 路由 | KV-event-aware routing，提高命中率 |
| 落地 | 长上下文场景降低单 Token 成本 |

与 Token Factory 关系：

- Copilot 和 Agent 场景天然长上下文、多轮对话、ReAct，KV Cache 是降低成本和保障体验的关键。

## 案例 01：H20 & R6KD 异构算力

### Slide 20

标题：

> H20 & R6KD：异构算力的最优角色匹配

核心表达：

- PD 分离让 R6KD 负责 Prefill，H20 负责 Decode。
- Weka GDS 让 KV Cache 跨节点 Offload 更高效。
- PD 分离 + 远端中心存储，是长文本 SLO 达标的高性价比方案。

环境：

| 类别 | 内容 |
|---|---|
| 硬件 | H20 8-GPU + R6KD 8-GPU，400G → 3.2T 东西向 RDMA |
| 存储 | 超云 CS13000 全闪 NVMe + WekaFS，配合 NVIDIA GDS |
| 软件 | vLLM + LMCache + CUDA 12.8，打通存储、网络和显存路径 |

收益：

| 指标 | 结果 | 说明 |
|---|---:|---|
| TTFT | ↓97% | KV 加载显著缩短 |
| 吞吐 | ↑39x | 读取带宽达 700 Gb/s |
| TPOT | ↓91% | Decode 更稳定 |
| 网络 | ↑6.8x | GDS 释放 RDMA 带宽 |

适合讲给 C 类：

- 地方智算中心常常是异构硬件组合，不可能只买最理想硬件。
- DaoCloud 能通过角色匹配和存储/网络优化，把异构算力组织成可达 SLO 的生产系统。

## 案例 02：DeepSeek-V3.2 / R1 on GB300

### Slide 21

标题：

> DeepSeek-V3.2 / R1 on GB300：跨代架构红利

核心表达：

- Native FP4、P/D 分离和 Nixl KV 传输，把 Blackwell Ultra 的算力与显存优势转成真实吞吐。

优化组合：

- NVFP4 量化版本，单机 2 卡容纳全量模型。
- Prefill EP2 压榨带宽，混合场景 TP2 优化 TTFT。
- Nixl 实现跨节点 KV 传输，3P1D 消除长文本 Prefill 瓶颈。
- 低并发开启 MTP 投机采样，提升 Decode 吞吐。

收益：

| 指标 | 结果 |
|---|---:|
| PD 混合吞吐 | 对比 H200 ↑20.8x |
| 纯 Prefill | ↑7.7x |
| TPOT | <60ms |
| R1 Prefill | 22.5K TGS/卡 |

补充结论：

- FP4 相比 FP8 混合吞吐翻倍。
- KV 显存占用从 100% 降至 25%。

适合讲给 C / D：

- DaoCloud 能把新一代硬件架构红利转成实际 Token 产能，而不是停留在硬件宣传参数。
- 对 D 类投资叙事，可证明 DaoCloud 能跟上最前沿硬件与引擎优化。

## 案例 03：MiniMax-M2.5 单节点高吞吐

### Slide 22

标题：

> MiniMax-M2.5：单节点 8 GPU 的高吞吐部署

核心表达：

- LWS 编排下采用 PD 分离、TP4 + EP、DP8、DeepEP 和 MTP，适配 MoE 模型负载特征。
- 在 P90 TTFT < 500ms 的 SLA 约束下，把单节点吞吐推到 7.3 万 tokens/s。

能力组合：

- 模型支持 Tool Call 与 Reasoning。
- vLLM v0.15.1 提供 OpenAI 兼容接口。
- NixlConnector 优化 KV Cache 传输。
- DeepEP 提升 All-to-All 通信效率。
- DeepGemm 全量预热。
- FP8 KV Cache 降低显存占用。

## 案例 04：海光 DCU Qwen3-30B

| 框架 | Flash-Attn-PA、Zero-Overhead、PCIe Custom AllReduce |
| 算子 | TopK 与 Renormalize 融合，降低 Decode 访存瓶颈 |

## 技术先进性素材归类

### 面向 C 类：地方智算中心

地方智算中心最关心：

- 已有 GPU / NPU / DCU 如何从资产变成收入。
- 异构硬件如何纳管和优化。
- 单位 Token 成本如何下降。
- SLA 如何进入生产级承诺。
- 高峰流量下如何保持稳定。
- 新硬件、旧硬件、国产硬件如何组合出可售能力。

可用素材：

- 单卡月收入从 0.52 万提升到 0.93 万，成本 0.68 万不变。
- H20 & R6KD 异构 PD 分离，TTFT ↓97%，吞吐 ↑39x。
- GB300 DeepSeek 混合吞吐较 H200 ↑20.8x。
- 海光 DCU Qwen3 吞吐 ↑49.5%，TPOT ↓50.3%。
- A800 通用优化成本 ↓约 40%。
- AI 网关、韧性、Planner、KV Cache、可观测闭环用于生产化运营。

### 面向 C 类：大型企业内部 MaaS / Token 供给平台

大型企业最关心：

- 内部 Agent / Copilot / Workflow 能不能稳定跑。
- 预算内体验是否稳定。
- 部门和应用增长后是否仍能控制成本。
- 长上下文、多轮对话、Tool Call、Reasoning 场景是否可支撑。
- 内部模型服务是否可审计、可授权、可限流、可降级。

可用素材：

- MiniMax-M2.5 单节点 73,495 tokens/s，P90 TTFT 270-490ms，P90 TPOT 19-35ms。

### 面向 B 类：企业内部使用与治理方

B 类不会主要关心底层算法细节，但会关心：

- 体验是否稳定。
- 预算是否可控。
- Agent / Copilot 是否能规模化使用。
- 高峰时是否影响关键业务。
- 内部应用成本能否归因。

可用转译：

- TTFT / TPOT 不是技术炫耀，而是用户首字响应和持续生成体验。
- KV Cache 和路由优化不是底层细节，而是让企业 Copilot 和 Agent 成本下降、响应稳定。
- 网关和观测不是运维页面，而是内部治理、审计、预算和服务质量保障。
