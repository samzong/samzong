Model × effort

Model rates use session exposure to each configuration as the denominator. A session can count under multiple configurations, so their n values are not additive. With a small n, zero corrections do not establish a consistently low rate; differences cannot be attributed to rules or models.

Monthly correction rate

Monthly rates count corrections by UTC event date. The denominator is active primary sessions with visible messages in that month; a long session can count in multiple months. Rates can exceed 100 and are not the probability a session was corrected. The latest month may be incomplete; a commit date does not prove that a session loaded the rule.

Clusters are inferred from this classification. A cluster is repeated across sessions when it appears in at least two distinct sessions. Counts below are detected counts; missed cases and missing sources can make them appear lower.

Repository ranking

Corrections per 100 primary sessions; n is visible. Task type, session length, configuration switches, and actual rule loading are unknown, so differences cannot be attributed to rules or models. Select a repository to expand its leading clusters.

Position within session

user_seq is the 1-based index of a user message in the index. It includes injections and is not a count of confirmed human turns. Prescreening excludes the first turn, so it cannot establish that no correction occurred there. The table shows the distribution of detected corrections.

Tokens and corrections

Missing usage is not treated as zero. Tokens reflect recorded workload, not dollar cost. More tokens may create more opportunities for correction or may result from rework after a correction; causal direction is unknown. Tokens for sessions that switch configurations are session totals. Groups are based on whether a correction was detected under the current filters. Sessions are deduplicated, and session tokens are not assigned to months or configurations.
